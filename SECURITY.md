# Security

Please report vulnerabilities privately through GitHub's "Report a vulnerability" button on this repository's Security tab, not in a public issue.

Include what is affected, how to reproduce it, and what an attacker could do with it. You will get an answer within a week.

## What matters most here

- **Runner keys.** A key lets its holder register a runner for the key's owner. The agent sends it only as the `x-runner-secret` header over TLS, the desktop app stores it encrypted, and neither logs it. Anything that leaks a key is in scope.
- **Session isolation.** Each editor session runs as its own Linux user inside the runner container. Escapes between sessions, or from a session into the agent, are in scope. Process-only quiescence retains the account and data until final cleanup. Cleanup revalidates the account uid before acting on a remembered identity. After retirement, pending sealed-data deletion retries cannot reap that uid again. This does not establish complete reader joining or protection against concurrent host-root account changes.
- **Runtime activity.** Required activity delivery retains the original process identity and sealing flags through retries, without copying diagnostic or prompt content into the fact. Admission expiry can stop its captured child while cleanup continues joining the original transport. The manager owns its readers and exit monitor and uses a pinned pidfd for child signals. Native account/descendant and wire qualification remain required; this does not establish diagnostic retention or deletion.
- **Agent shutdown.** Original command, telemetry, eviction and status producers and cancellation callbacks must finish before session cleanup and sidecar/channel disposal. The nested command listener also owns status/model/command lanes, admitted progress callbacks and every cleanup drain, including partial setup. The command stream also joins its original handlers and detached acknowledgements before releasing request gates; completed observation records keep failure facts without arbitrary exception data. Startup retains its original cancellation callback task through host shutdown and physical cleanup; callback failure cannot bypass that join or enter an acknowledgement message. A failed lane cancels its peers; an original task that ignores cancellation holds shutdown open. All four control channels outlive relays, sidecars and sessions. The final entry-point exception handler reports only a class and exits nonzero; this does not establish content-safe diagnostics elsewhere. Controlled lifetime tests do not establish real signal/transport or provider termination behavior.
- **Prompt cancellation.** Stop owns original execution, settling, release and cancellation-callback tasks, including demand handoff and recovery replacement. Callback failure cannot bypass peer cancellation or the join. The inner model-demand lifetime joins its original callbacks and every returned demand task after native rejection or queue withdrawal; failed preparation still joins registered callbacks. An outstanding queue probe remains owned through completion. Matching admission closes during that join; unrelated sessions remain independent. Completed command references are dropped before cleanup callbacks are joined, and finished settling-task references are cleared to release their exception data. These local ownership rules do not prove native queue interruption, complete content deletion or physical memory erasure.
- **Transient request cancellation.** Each request owns its original cancellation callbacks through execution completion. Retired requests remain joinable, callback failure cannot skip peers, and Stop/Quiesce keep matching admission closed through request joining and physical cleanup. Registry shutdown joins current and retired owners before command gates are released. Controlled tests do not establish actual HTTP cancellation, account/key cleanup or complete content deletion.
- **GPU work shutdown.** The power executor joins admitted activation and delivery roots as well as original cancellation callbacks. Repeated drain callers share one completion task, and both admission paths close before its snapshot. Completed observation records retain failure facts without arbitrary exception payloads. Controlled tests do not establish actual GPU effects, native cleanup or complete content erasure.
- **Sidecar shutdown.** Artifact and workspace services retain stopping owners, close operation admission and join original initialization, reads, writes and cancellation callbacks before releasing their handles. Repeated stop and global disposal share that join. Slow warnings and conservative loss accounting do not authorize early cleanup. An upload body failure still joins the original call response; cleanup errors cannot mask the body failure. Controlled tests do not establish real transport termination, account/key cleanup or complete content erasure.
- **The model VFS shim.** `liboffloadr_model_vfs.so` is preloaded into the editor process and talks to the agent over a Unix socket. Bugs that let the editor read or write outside its session through that socket are in scope.
- **Sealed storage.** In sealed mode a session's inputs, outputs, temp files and workspace state are meant to stay in memory-backed storage and out of logs and core dumps. Anything that makes the runner write them to disk, or keep them after the session ends, is in scope, and so is anything that makes a sealed session accept a transfer that is not sealed to it or use a reader key beyond its session. A host that reads the machine's memory is not.
- **The desktop supervisor.** It runs the docker or podman CLI. Anything that makes it run a different image, mount different folders, or expose the key on a command line is in scope.

Issues in ComfyUI, Forge Neo or their custom nodes belong with those projects. Report them here as well when the runner makes them worse.
